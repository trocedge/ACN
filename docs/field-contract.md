# ACN 字段契约表

> 版本：schema 1.1 ｜ 日期：2026-11-10
> 作用：数据层与展示层之间的唯一字段依据。界面改造前请以此表确认字段清单，避免双向猜测。
> 依据：`data/conferences.yml` 实际产出（383 条 / 2357 届次 / 2939 时间节点）

---

## 1. 顶层条目（每行一个会议）

| 字段 | 类型 | 语义 | 必填 | 来源 | 展示用途 | 备注 |
|---|---|---|:---:|---|---|---|
| `schema_version` | string | 数据结构版本 | ✅ | 转换脚本 | 兼容性判断 | 当前 `1.1`，结构变更时递增 |
| `status_as_of` | string | 状态字段的生成时刻（北京时间） | ✅ | 转换脚本 | 说明状态是快照 | 格式 `YYYY-MM-DDTHH:mm:ss+08:00` |
| `title` | string | 会议简称，不含年份，大写 | ✅ | 源档案 | 行式主标题 | 不得修改原值 |
| `description` | string | 会议全称 | ✅ | 源档案 | 副标题/详情 | — |
| `sub` | string | CCF 学科代码 | ✅ | 源档案 | **筛选项** | 10 类：AI/CG/CT/DB/DS/HI/MX/NW/SC/SE |
| `rank` | object | CCF / CORE / THCPL 评级 | ⭕ | 源档案 | **筛选项**、徽标 | 项目内核字段，不得因对齐参考站删除 |
| `dblp` | string | dblp 后缀 | ⭕ | 源档案 | 外部链接 | 同上 |
| `source_file` | string | 源档案相对路径 | ✅ | 转换脚本 | 回溯、排错 | 新增字段 |
| `events` | list | 历届信息 | ✅ | 源档案 `confs` | 行式列表主体 | 字段名由 `confs` 改为 `events` |

## 2. 届次条目（events[]）

| 字段 | 类型 | 语义 | 必填 | 来源 | 展示用途 | 备注 |
|---|---|---|:---:|---|---|---|
| `year` | int | 年份 | ✅ | 源档案 | **筛选项** | — |
| `id` | string | 全局唯一标识 | ✅ | 源档案 | 详情锚点 | 全库唯一，校验脚本强制 |
| `link` | string | 官网 | ✅ | 源档案 | 跳转 | — |
| `timeline` | list | 关键时间节点 | ✅ | 源档案 | 行式主内容 | — |
| `timezone` | string | 原始时区口径 | ✅ | 源档案 | 双时区展示左侧 | **保留原值，禁止静态替换** |
| `timezone_utc_offset` | int / null | 可确定的 UTC 偏移 | ✅ | 转换脚本 | 换算依据 | `PT` 等 35 条为 `null` |
| `date` | string | 会议日期（英文原值） | ⭕ | 源档案 | 详情 | 人类可读，非结构化 |
| `date_zh` | string / null | 中文日期 | ⭕ | 转换脚本 | 中文界面 | 覆盖 2105/2357；无法确定留 `null` |
| `place` | string | 地点（英文原值） | ⭕ | 源档案 | 详情 | — |
| `place_zh` | string / null | 中文地点 | ⭕ | 转换脚本 | 中文界面 | 覆盖 1724/2357；**城市名保留原文，不编造译名** |
| `status` | enum | 届次状态 | ✅ | 转换脚本 | **默认过滤** | `active` / `past` / `tbd` / `unknown` |
| `status_basis` | enum | 状态判定依据 | ✅ | 转换脚本 | 正确性说明 | `beijing` / `local_naive` / `none` |

## 3. 时间节点（timeline[]）

| 字段 | 类型 | 语义 | 必填 | 来源 | 展示用途 | 备注 |
|---|---|---|:---:|---|---|---|
| `deadline` | string | 截止日（ISO 8601） | ✅ | 源档案规范化 | 主展示 | `'YYYY-MM-DDTHH:mm:ss'` 或 `TBD` |
| `deadline_beijing` | string / null | 换算后的北京时间 | ⭕ | 转换脚本 | **双时区展示右侧** | 成功 2713 条；偏移不确定时为 `null` |
| `comment` | string | 轮次说明 | ⭕ | 源档案 | 辅助文字 | 如 `first round` |
| 其他扩展键 | any | 摘要截止日、复议、录用通知等 | ⭕ | 源档案 | 按需 | 一律保留，不删改 |

## 4. 派生字段的正确性边界（重要）

| 场景 | 处理 | 原因 |
|---|---|---|
| `AoE`（1540 条） | 保留原值，`timezone_utc_offset = -12`，按 +20 小时换算北京时间 | AoE = UTC-12，与北京时间差 20 小时，静态替换会导致整批截止日错一天 |
| `PT`（35 条） | 保留原值，`timezone_utc_offset = null`，`deadline_beijing = null` | 存在夏令时切换，无法用固定偏移表示，须由展示层按具体日期判定 |
| `TBD`（98 条） | 原值保留，不推算、不补写 | 未公布日期，编造即失真 |
| 日期/地点中文化 | 仅按白名单与结构化规则转换，不匹配则 `null` | 不编造城市译名与月份 |
| `status` | 生成时刻快照，随 `status_as_of` 一起记录 | 长期方案应由 CI 定时重算 |

## 5. 展示层使用建议

1. 默认只展示 `status = active` 的届次（当前 114 条），历史用切换按钮查看（2155 条 `past`）。
2. 筛选维度直接用 `sub` / `year` / `rank.ccf` / `status`，无需额外计算。
3. 截止日必须**双时区并列**：左侧 `deadline` + `timezone`，右侧 `deadline_beijing`；后者为 `null` 时显示「需按日期换算」而不是留白。
4. `date_zh` / `place_zh` 为 `null` 时回退英文原值，不要显示空字符串。
