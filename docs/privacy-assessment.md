# 隐私与第三方资源评估

> 日期：2026-11-10
> 背景：项目若要面向全校同学开放使用，需明确页面引入了哪些第三方资源。
> 本文只做评估与建议，**不擅自删除或修改现有页面代码**。

---

## 1. 现状核查

在仓库 `index.html` 中可查到：

| 项 | 位置 | 说明 |
|---|---|---|
| Google AdSense 账号标识 | `<meta name="google-adsense-account" ...>` | 页面声明了广告账号 |
| 隐私弹窗 | `privacy-modal.css` / `privacy-modal.js` | 页面加载了独立的隐私提示组件 |
| 外链 | 会议官网、`dblp`、参考站等 | 用户主动点击才跳转，不属于自动加载 |

此外 README 中列出了多个外部服务入口（Web 主站、表格站、小程序、MCP 服务等），这些属于产品形态说明，不构成页面自动请求。

---

## 2. 面向全校服务时的关注点

| 关注点 | 为什么 | 建议 |
|---|---|---|
| 第三方脚本自动加载 | 校园网环境下可能触发请求失败、加载阻塞或合规询问 | 梳理所有自动加载的第三方资源清单，逐项确认必要性 |
| 隐私告知是否明确 | 面向全校同学，需说明收集什么、用途、保存多久 | 隐私弹窗应列出具体第三方名称与用途，避免笼统表述 |
| 广告与研究工具的适配性 | 学术信息汇总站点引入广告，容易影响可信度与阅读体验 | 由项目组决定是否保留；若保留，需与信息主体明确区分 |
| 数据本身是否涉及个人信息 | 当前数据为公开的会议信息，不含学生个人数据 | 保持现状；若未来加入账号、收藏、订阅，需重新评估 |

---

## 3. 三个可选方案

| 方案 | 做法 | 优点 | 代价 |
|---|---|---|---|
| A · 保留并说明 | 完善隐私弹窗文案，列出第三方名称、用途、退出方式 | 改动最小 | 仍有第三方请求 |
| B · 按需加载 | 第三方脚本改为用户交互后才加载 | 首屏更干净、请求可控 | 需改前端 |
| C · 移除 | 去掉广告相关声明与脚本，仅保留纯信息展示 | 最适合校园公共服务 | 失去既有广告位 |

**推荐顺序**：短期 A（补文案），中期 B（前端改造时顺带做），若定位为校内公共服务则考虑 C。

---

## 4. 建议写入隐私弹窗的要素

1. 本站点仅展示公开的会议与竞赛截止日信息；
2. 不要求注册、不采集学生身份信息；
3. 列出自动加载的第三方资源名称与用途；
4. 说明浏览器本地存储的使用范围（如收藏、时区偏好）；
5. 给出关闭或退出第三方统计的方式；
6. 数据纠错与联系入口（指向 `CONTRIBUTING.md`）。

---

## 5. 边界

- 本文为评估建议，落地需由界面负责人修改 `index.html` 与隐私组件；
- 本次数据格式改造未引入任何新的第三方请求；
- 未对现有页面做任何删除或替换。
