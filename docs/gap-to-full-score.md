## 一、数据正确性与规范（当前 95%）

| # | 差距在哪 | 为什么还没满分 | 补齐动作 |
|---|---|---|---|
| 01 | 时区原值仍有语义重叠 | `AoE` 1540 条与 `UTC-12` 288 条并存、`UTC` 72 与 `UTC+0` 74 并存；`docs/timezone-dictionary.md` 只给了别名建议，**源数据未归一化** | 另开独立变更加别名表并逐条核对，不在转换脚本里隐式改写 |
| 02 | `PT` 35 条无北京时间 | `timezone_utc_offset` 与 `deadline_beijing` 均为 `null`，夏令时未做按日期判定；目前只是留空，**没有可执行的运行时换算实现** | 提供按日期判夏令时的换算函数，并给展示层调用示例 |
| 03 | `TBD` 98 条无跟踪机制 | 只有标记，没有「何时复查、由谁补、来源链接」字段或流程 | 增加复查日期与来源备注字段，纳入定期核对清单 |
| 04 | 中文日期缺 252 条 | 覆盖 2105/2357，剩余多为含括号、多段、非标准月份写法；留空虽不编造，但**全校阅读仍有断点** | 扩充结构化解析规则，逐类补覆盖并给覆盖率回归 |
| 05 | 中文地点缺 633 条 | 覆盖 1724/2357；国家白名单有限，且**城市名一律保留英文**，未建立可维护译名表 | 建立可扩充地名表（人工确认后入库），不自动猜测 |
| 06 | 录取率 23 份断链只告警 | `validate_data.py` 仅列为 WARN，`accept_rates/` 与会议档案仍靠标题松散匹配，**未建立 id 级外键** | 定义关联键与一致性校验，输出完整断链清单 |
| 07 | `status` 是快照且部分近似 | `status_as_of` 固化在生成时刻，长期会过期；35 条 `status_basis=local_naive` 用本地时间近似判定 | 由 CI 定时重算；近似条目标注不确定范围 |
| 08 | 校验规则覆盖不全 | 当前 ERROR 规则集中在必填、日期格式、id 唯一、条数一致；**未校验** `year` 取值范围、`rank` 枚举、`link` 可达性、timeline 时间顺序与重复节点 | 扩充分级规则，先加 WARN 观察再升 ERROR |
| 09 | 两套格式仍并存 | 老链路 `allconf.json` 保留空格分隔日期，新表用 ISO 8601；**未收敛到单一规范**，前端需兼容两者 | 定迁移计划，明确老链路何时切换或长期并存 |
| 10 | 无版本迁移与兼容测试 | `schema_version` 只是标识；旧展示层读到 1.1 依赖「忽略不认识字段」的约定，**没有自动化兼容性验证** | 增加迁移脚本与跨版本读取测试 |
