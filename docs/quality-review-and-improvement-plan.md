# ACN 项目质量评估与改进计划书

> 版本：v1.0 ｜ 编制日期：2026-11-10
> 评估对象：ACN（Academic Competition News，学术会议与竞赛截止日追踪站）
> 评估口径：以「面向全校同学开放使用」的产品标准衡量，不局限于单次任务交付
> 依据：仓库 `github.com/trocedge/ACN` 主干实拆（383 份会议档案 / 712 份 yml）、`scripts/DATA_LOADING.md`、参考站 `oseddl.openatom.club` 公开文档、本次数据格式改造成果
> 说明：本文所有结论均基于可核查的仓库事实，未使用推测数据；改进项标注责任边界，跨模块事项需与项目组协同。

---

## 一、项目现状（评估基线）

| 项 | 实测 |
|---|---|
| 会议档案 | 383 份，分布在 10 个学科目录（AI / CG / CT / DB / DS / HI / MX / NW / SC / SE）+ `types.yml` |
| 全仓 yml | 712 份，其中 `accept_rates/` 约 329 份为历史录取率数据 |
| 数据规模 | 2357 个届次（events）、2939 个时间节点（timeline） |
| 技术栈 | 前端 Rust / Trunk / WASM（`src/` + `Cargo.toml`），数据层 Python（`scripts/build_data.py` + `merge.py`），边缘服务 `worker/` + MCP |
| 数据链路 | 散 yml → `merge.py` 合并 → `public/conference/allconf.json` → 拆分 `initial.json` / `parts/*.json` 按需加载 |
| 生态 | Web 主站、表格站、小程序、CLI、Raycast、SwiftBar、iCal、Chrome 扩展、TUI、MCP 只读服务 |
| 本次改造 | 新增 `scripts/build_compact.py` 与 `data/conferences.yml`，产出单表 383 条，老 yml 零改动 |

## 二、10 条优点

| # | 优点 | 事实依据 | 为什么值钱 |
|---|---|---|---|
| 01 | 数据源结构化程度高 | 383 份档案按 CCF 学科分目录，字段含 `title`/`sub`/`rank`/`dblp`/`confs` | 机器可读、可批量处理，不是散文本 |
| 02 | 贡献流程成熟 | README 定义 fork → 改 yml → PR，附完整字段表与必填标记 | 多人协作有规可依，新人能按表填 |
| 03 | 数据约定写进文档 | 仅给日期默认 `23:59:59`、未给时区默认 `AoE`、未公布用 `TBD` | 避免同一事实多种写法，减少数据歧义 |
| 04 | 合并链路自动化 | `build_data.py` 调 `merge.py` 生成全量 yml/json | 无需人工拼装，改一份档案即可全量重算 |
| 05 | 首屏加载有设计 | `initial.json` 只装最新/未来届次，历史拆 `parts/history-*.json`，失败回退全量 JSON | 大体积数据下仍可控制首包大小 |
| 06 | 多端与扩展生态完整 | 小程序 / CLI / iCal / Raycast / Chrome 扩展 / TUI / MCP | 同一份数据可服务不同使用习惯，扩展性强 |
| 07 | 面向 AI 客户端的只读接口 | `worker/mcp` 提供 Streamable HTTP，支持 CCF/CORE 筛选、分页、时区转换 | 具备被智能体直接检索的能力，符合当前技术方向 |
| 08 | 时区口径有明确规范 | 支持 `UTC-12`~`UTC+12`、`AoE`、`PT`（自动夏令时）；本次改造保留原值并补 `timezone_utc_offset` | 截止日类产品的核心正确性，未做粗暴替换 |
| 09 | 存在多层测试 | `scripts/test_*.py` 20+ 项 Python 单测、浏览器测试、`cargo test` | 有回归基础，改动可被验证 |
| 10 | 本次改造可回退、不侵入 | 新脚本只读老档案，产出独立文件，`git diff` 确认老文件零改动 | 风险隔离，失败可直接删除新增文件恢复原状 |

## 三、20 条缺点（逐条：现象 → 为什么是问题 → 改进方向）

### A 组 · 面向全校使用的产品可用性（01—06）

| # | 缺点 | 为什么是问题 | 改进方向 |
|---|---|---|---|
| 01 | 定位面向研究者，本科生看不懂 | README 写 "Helping researchers track worldwide conference ddls"，界面与数据满是 CCF A/B/C、SIGMOD、dblp 等术语；全校同学多数未接触过学术会议投稿 | 增加「新手引导」层：用一句话解释「这是什么、我该看哪个日期、CCF 等级是什么」，提供术语表 |
| 02 | 界面与数据缺中文化 | `index.html` 为 `lang="en"`，`date` 形如 `June 12-17, 2022`、`place` 形如 `Philadelphia, PA, USA` | 前端 i18n + 数据层补 `date_zh` / `place_zh`，与英文原值并存，不覆盖原始事实 |
| 03 | 截止日缺「北京时间」直观展示 | 2357 个届次中 `AoE` 1540 条（= UTC-12），与北京时间差 20 小时；同学按本地直觉判断会错过截止 | 双时区并列显示（原始时区 + 换算值），并在页面显著标注换算规则；`PT` 35 条按日期动态判夏令时，不做静态替换 |
| 04 | 行式列表缺筛选与检索 | 383 会议 × 2357 届次，行式展示一屏装不下；无学科/年份/等级筛选，无模糊搜索 | 加筛选栏（学科 `sub`、年份、CCF 等级）+ 前端模糊搜索 + 分页或虚拟滚动 |
| 05 | 默认视图未区分「已过期 / 进行中 / 未公布」 | 数据含 2020 年至今的历史届次，行式列表会被过期条目淹没，`TBD` 98 条也混在一起 | 数据层补 `status`（past / active / tbd），默认只展示 `active`，历史可切换查看 |
| 06 | 移动端体验未验证 | 全校同学以手机访问为主；当前为 Rust/WASM + 表格型页面，仓库未见移动端适配验收记录 | 补 7 视口响应式回归与真机验证，行式卡片在窄屏改为纵向堆叠 |

### B 组 · 数据质量与规范（07—11）

| # | 缺点 | 为什么是问题 | 改进方向 |
|---|---|---|---|
| 07 | 两套日期格式并存 | 老档案为 `'2020-09-01 23:59:59'`，新格式为 ISO 8601 `'2020-09-01T23:59:59'`，前端需同时兼容 | 确立单一规范（ISO 8601），转换脚本统一产出，CI 加格式校验门禁 |
| 08 | 时区取值不统一 | 实测 `AoE` 1540、`UTC-12` 288、`UTC+0` 74、`UTC` 72、`PT` 35 等多种写法并存，语义重叠 | 建立时区字典与归一化映射表；`PT` 等 35 条保留原值并标注「需按日期换算」 |
| 09 | 缺 PR 前强制数据校验 | 仓库有 `conference-yaml-schema.yml`，但未见合并前强制校验的门禁说明；本次 `--check` 0 问题源于数据本身干净，不代表有防线 | 把必填字段、日期格式、时区白名单、`id` 唯一性校验接入 CI，失败即阻断合并 |
| 10 | 录取率数据与会议数据靠标题关联 | `accept_rates/` 约 329 份独立维护，与 `conference/` 通过标题松散对应，改名或重名会断链 | 建立 `id` 级外键关联并加一致性校验，输出断链清单 |
| 11 | 字段语义边界不清 | 老字段 `sub`（学科）与新需求「分类」易混淆；`rank`/`dblp` 属项目内核但参考站无对应字段，直接照抄会丢失 | 输出《字段契约表》明确每个字段的语义、是否必填、展示位置，作为前后端唯一依据 |

### C 组 · 工程与发布（12—16）

| # | 缺点 | 为什么是问题 | 改进方向 |
|---|---|---|---|
| 12 | 生成物入库策略未定 | `DATA_LOADING.md` 写明生成文件由 CI 组装且被 Git 忽略，本次却随仓库提交 776 KB 的 `data/conferences.yml`，两种口径冲突 | 由项目组定二选一：① 提交产物（便于前端直接对接）② 加入 `.gitignore` 由 CI 生成；当前按①执行，需在文档注明并保持一致 |
| 13 | 测试跨平台不达标 | 82 项 Python 单测中 14 项报错：`WinError 32` 临时 sqlite 文件占用、`unittest.loader._FailedTest` 缺依赖；**干净副本对照同样 14 错**，属仓库既有问题 | 修临时文件清理（上下文管理器 + 延迟释放）、补齐 `requirements.txt` 依赖、在 CI 的 Linux 环境跑全量 |
| 14 | 自动发布链路尚未可见 | 工程化与 Pages 部署由项目组其他成员负责，当前 B 产出尚未接入 CI 自动刷新，改了 yml 需手动重跑脚本 | 在 CI 增加一步「数据校验 → 生成新表 → 部署」，与 Pages 构建串成一条流水线 |
| 15 | 前端技术栈门槛偏高 | Rust / Trunk / WASM 对负责界面改造的同学学习成本高，本地启动需 `build_data.py` + `trunk serve` 两步 | 补一份中文《本地开发上手》与一键启动脚本，降低协作门槛 |
| 16 | 缺运行监控与失败告警 | 数据过期、脚本失败、页面不可用时无感知；面向全校服务，静默失败影响面大 | 定时探活 + 结构化日志 + 通知（与负责通知脚本的成员对接） |

### D 组 · 协作治理与交付规范（17—20）

| # | 缺点 | 为什么是问题 | 改进方向 |
|---|---|---|---|
| 17 | 贡献文档为英文且指向上游仓库 | README 让 PR 提到 `ccfddl/ccf-deadlines`，而本项目是 fork；新成员容易提错仓库 | 补中文 `CONTRIBUTING.md`，明确「本仓库 PR 到本项目分支」，标注上游同步策略 |
| 18 | 第三方追踪与隐私说明不足 | `index.html` 含 Google AdSense 与 `privacy-modal`，面向全校的服务引入第三方脚本需明确告知 | 评估是否移除广告脚本；保留则在隐私弹窗与页脚明确列出第三方与用途 |
| 19 | 文档分散无索引 | `DATA_LOADING.md`、`SHARE_CARDS.md`、README、schema 各自为政，缺统一入口 | 建 `docs/README.md` 索引，按「数据 / 前端 / 部署 / 贡献」四类归档 |
| 20 | 本次改造未与前端字段契约对齐 | 新表保留全部老字段，行式界面只会展示子集；未定义 schema 版本与迁移说明，后续收敛易返工 | 增加 `schema_version`、变更日志，并与界面负责人确认字段清单后再精简输出 |

## 四、改进计划书（依据 20 条缺点）

### 4.1 目标与约束

| 项 | 内容 |
|---|---|
| 目标 | 把 ACN 从「研究者工具」提升到「全校同学可直接使用的截止日服务」 |
| 硬约束 | ① 不破坏原有数据链路，老 yml 零改动；② 不丢失 `rank` / `dblp` 等项目内核字段；③ 时区语义不得被静态替换；④ 所有改动走分支 + PR，不直接推主干 |
| 责任边界 | 数据层（B）可独立完成 07—12、20；界面层（A）负责 01—06；工程/发布（C、D）负责 13—16、18；协同项 17、19 |
| 验收口径 | 每阶段跑数据校验、回归测试、响应式与无痕窗口可用性检查 |

### 4.2 分期与优先级

| 阶段 | 覆盖缺点 | 交付物 | 验收 |
|---|---|---|---|
| P0 · 数据正确性（1—2 天，B 独立完成） | 07、08、09、10、11、12、20 | 字段契约表、时区字典、CI 校验脚本、schema 版本与变更日志 | `--check` 0 问题；老链路 `build_data.py` 正常；`AoE` 1540 条语义不变 |
| P1 · 全校可用性（需与 A 协同） | 01—06 | 中文化与新手引导、筛选/搜索、状态字段、双时区展示、移动端回归 | 7 视口无横向溢出；无痕窗口可用；随机抽 10 条截止日换算正确 |
| P2 · 工程与治理（需与 C/D 协同） | 13—19 | 测试修复、CI 流水线接入、中文贡献指南、文档索引、监控告警 | CI 在 Linux 全绿；生成物策略定稿；探活告警可触发 |

### 4.3 核心机制说明

1. **单一数据源**：老 `conference/**/*.yml` 仍是唯一事实来源，所有新格式由脚本派生，杜绝手工双写。
2. **时区双轨**：保留 `timezone` 原值，另存 `timezone_utc_offset`；对 `PT` 等无法静态换算的条目留空并由前端按日期判定，避免 1540 条 `AoE` 被错误偏移。
3. **渐进式字段收敛**：先全量保留，待界面字段契约确认后精简，避免不可逆删除。
4. **校验前置**：把「必填 / 日期 / 时区 / id 唯一」做成 CI 门禁，把事后检查变成事前阻断。
5. **可回退**：每阶段改动限于新增文件与配置，任何阶段失败均可删除新增内容恢复。

### 4.4 风险提示

| 风险 | 影响 | 缓解 |
|---|---|---|
| 时区误换算 | 全校同学按错误截止日准备材料 | 保留原值 + 双时区展示 + 抽样人工核对 |
| 生成物策略未定稿 | 仓库体积膨胀或前端读不到数据 | P0 阶段由项目组拍板并写入文档 |
| 跨模块依赖 | A/C/D 进度影响 P1/P2 | B 的 P0 全部设计为可独立交付，不阻塞他人 |
| 测试基线本身有 14 项既有错误 | 无法用「全绿」证明改动无回归 | 采用「干净副本对照」口径，如实记录 |

## 五、开发执行指令（提示词 · 可复制）

### 5.1 总指令（一次性粘贴）

```
你是本项目的数据工程执行者。请严格按以下约束完成 ACN 数据格式改造，不得自行扩大范围。

【项目背景】
ACN 是学术会议/竞赛截止日追踪站，老数据为 conference/<学科>/<会议>.yml 共 383 份，
由 scripts/build_data.py 合并成 public/conference/allconf.json 供前端（Rust/WASM）消费。
目标是产出一份适合「行式展示」的精简大表，供前端改造后使用，面向全校同学。

【硬约束，违反即停止】
1. 老 yml 文件只读，一个字都不许改、不许删、不许搬位置。
2. 不删除任何老字段（title/description/sub/rank/dblp/confs 等一律保留），
   界面「仅保留重要内容」属于展示层，数据层不做不可逆删减。
3. 不造 category，不拆分 conferences/competitions/activities 三张表；只产出一份表。
4. 时区保留原值，绝不把 AoE 静态替换成 Asia/Shanghai；AoE=UTC-12，与北京时间差 20 小时，
   静态替换会让 1540 条截止日整体错一天。PT 有夏令时，留空由前端按日期判。
5. 不造数据：TBD 原样保留，未公布日期不得编造，不新增仓库中不存在的会议或活动。
6. 所有改动走独立分支 + PR，不直接推 main。

【要做的】
1. 编写转换脚本：扫描散 yml → 合并为一份表；confs 改名 events；
   deadline 由 'YYYY-MM-DD HH:mm:ss' 归一为 ISO 8601（带 T）；
   保留 timezone 原值并补 timezone_utc_offset（能确定的填数字，PT 等留 null）；
   新增 source_file 便于回溯。
2. 编写校验：必填字段、日期格式、时区白名单、id 唯一、产出条数与源文件数一致；
   提供 --check 只校验不落盘的模式。
3. 输出《字段契约表》：字段名、语义、是否必填、展示位置、来源。
4. 输出《验证报告》：条数、日期规范化数量、时区分布、校验结果、老链路是否照常、老文件是否零改动。
5. 所有代码写中文注释，命名清晰，不使用任何外部 AI 工具或平台名称。

【验收】
转换脚本跑完 0 报错；产出 383 条且回读一致；老链路 build_data.py 照常生成 allconf.json；
git diff 中只有新增文件；干净副本对照测试的错误数不增加。

【先给方案摘要，确认后再动手；每一步做完报告结果与风险，不要静默跳过。】
```
