# ACN 使用入门与术语说明

> 面向：第一次接触学术会议截止日的全校同学
> 日期：2026-11-10
> 说明：本文只解释仓库中已有概念，不补充外部未经核实的信息。

---

## 1. 这个站点是做什么的

一句话：**把各个学术会议、竞赛的「投稿截止日」集中列出来，避免错过时间。**

每条记录通常包含：会议名称、学科分类、评级、举办年份、官网链接，以及若干个关键时间点（摘要截止、全文截止、结果通知等）。默认应该只看**还没过期**的条目，历史条目可以切换查看。

如果你只是想找「最近还能投的会」，看这三个字段就够了：

| 看什么 | 字段 | 说明 |
|---|---|---|
| 哪个会 | `title` + `description` | 简称与全称 |
| 什么时候截稿 | `timeline[].deadline` | **注意看时区** |
| 去哪投 | `link` | 会议官网 |

## 2. 术语表

| 术语 | 含义 | 常见误区 |
|---|---|---|
| `CCF` | 中国计算机学会对会议/期刊的分级 | 不是难度排名，也不代表投稿一定更难 |
| `rank.ccf` = A / B / C | CCF 推荐列表中的等级 | 等级高≠适合自己，选方向比选等级重要 |
| `rank.core` / `rank.thcpl` | 另外两套评价体系（CORE、THCPL） | 三套体系口径不同，不要互相换算 |
| `sub` | 学科代码，如 `AI`（人工智能）、`DB`（数据库）、`SE`（软件工程） | 是分类标签，不是专业名称 |
| `dblp` | 计算机文献索引站 DBLP 的检索后缀 | 用来查该会议历年论文，不是投稿入口 |
| `deadline` | 投稿截止时刻 | **必须连同 `timezone` 一起看**，见第 3 节 |
| `abstract_deadline` | 摘要截止（部分会议才有） | 不等于全文截止 |
| `rebuttal_deadline` | 复议/作者回应截止 | 在初审结果之后，不是投稿时间 |
| `decision_deadline` | 录用结果通知时间 | 不是需要提交材料的时间 |
| `comment` | 轮次说明，如 `first round` | 同一会议可能有多轮截止 |
| `TBD` | To Be Decided，官方尚未公布 | **不是「没有截止日」，也不是 0 点**，不要自行填值 |
| `AoE` | Anywhere on Earth，全球任意时区的最后时刻 | 见下节，最容易踩坑 |
| `PT` | 美国太平洋时间 | 有夏令时，不能按固定时差口算 |
| `status` | 数据层标注的届次状态：`active` / `past` / `tbd` | 是生成时刻的快照，不是实时计算 |

### `sub` 学科代码对照

| 代码 | 方向 | 代码 | 方向 |
|---|---|---|---|
| `AI` | 人工智能 | `NW` | 网络 |
| `DB` | 数据库 / 数据挖掘 / 信息检索 | `SC` | 网络与系统安全 |
| `SE` | 软件工程 / 操作系统 / 程序设计语言 | `DS` | 体系结构 / 并行 / 存储 |
| `CT` | 计算理论 | `CG` | 图形学 |
| `HI` | 人机交互 | `MX` | 交叉 / 新兴方向 |

## 3. 最容易出错的一件事：时区

**同一个截止时刻，按不同时区理解可能差一整天。**

数据里 `AoE` 出现 1540 次，它是 UTC-12，比北京时间（UTC+8）**晚 20 小时**。举例：

```
deadline: 2021-07-02T17:00:00   timezone: AoE
换算后北京时间: 2021-07-03T13:00:00
```

如果按「7 月 2 日」准备，实际北京时间截止是 **7 月 3 日下午 1 点**；反过来若把 `AoE` 当成北京时间，就会少算一整天。

### 页面使用约定

1. 截止日**双时区并列显示**：左边原始值 + 原始时区，右边换算后的北京时间。
2. 换算值为空时（如 `PT` 的 35 条，涉及夏令时），显示「需按日期换算」，**不要显示一个猜出来的时间**。
3. `TBD` 显示「尚未公布」，不显示任何推算日期。
4. 涉及重要投递决策时，以会议官网公布的时间为准，本站点数据仅作汇总参考。

## 4. 筛选建议

| 想找什么 | 用哪个字段 |
|---|---|
| 某个方向的会 | `sub` |
| 某一年的会 | `events[].year` |
| 某个等级的会 | `rank.ccf` |
| 还能投的会 | `status = active`（默认视图） |
| 历史记录 | `status = past`（切换查看） |
| 尚未公布时间的会 | `status = tbd` |

---

## 5. 数据从哪来、怎么纠错

- 每条数据对应仓库里 `conference/<学科>/<会议>.yml` 一份档案，`source_file` 字段记录了具体路径。
- 数据由社区通过 Pull Request 维护；发现错误请按 `CONTRIBUTING.md` 的流程提交更正。
- 站点数据为人工维护汇总，**存在滞后或口径差异的可能**；关键时间请以会议官网为准。

---

## 6. 边界说明

- 本项目只做截止日信息汇总，不提供投稿代理、代写、查重等服务。
- 页面可能包含第三方统计或广告脚本，详见《隐私与第三方资源评估》。
- 数据中的评级、地点、日期均为源档案原值，中文辅助字段只做确定性转换，未覆盖部分保留原文。
