# 项目范围与收录约定

> 状态：方向已按学长 2026-11-16 审计意见确认，白名单 84 项已于 2026-11-17 按官方目录填入。
> 本文只定「收什么 / 目录怎么组织」的口径，不删任何已有数据。

## 1. 项目主线

ACN 的主线收录对象是**大学生竞赛白名单**，具体指中国高等教育学会《2024 全国普通高校大学生竞赛分析报告》竞赛目录，共 84 项。会议（学术会议 DDL）属于从上游 `ccfddl/ccf-deadlines` fork 时继承的历史数据，不再是新增数据的重点方向。

> 名称说明：学长口径里的「教育部白名单」，在高校场景对应的是上述 84 项目录（高校普遍用于保研加分与学科竞赛统计）。教育部另有一份 47 项名单，面向**中小学生**，学段不符，本项目不采用。两份名单的取舍理由见 `docs/whitelist-competitions.md` 第 1 节。

- 新增数据优先顺序：白名单 84 项竞赛 > 其它面向学生的赛事 / 活动 > 学术会议（仅维护已有，不新增）
- 判断依据：一条数据是否进主线，看它是否在 84 项目录里，序号能对上（见 `docs/whitelist-competitions.md`）

## 2. 目录命名约定（回应学长建议①）

学长指出「目录名依旧是 `conference`，但主要记录竞赛和活动，似乎可以规范化」。这里分清两层：

| 层 | 现状 | 约定 |
|---|---|---|
| 会议档案目录 | 384 份上游继承的会议数据已整体迁至 `archive/conference/`，git 历史完整保留、可回溯 | 顶层不再有 `conference/` 目录。归档目录只读维护，不新增 |
| 竞赛主线目录 | 新建 `competition/`，内含 `whitelist.yml`（84 项竞赛）、`types.yml`（12 类分类定义）、收录说明 | 新增竞赛在 `whitelist.yml` 追加条目，`sub` 取 `types.yml` 的分类短码；`seq` 沿用官方序号 |
| 前端产物路径 | 仍为 `public/conference/` | 保持不变，避免牵动前端引用；产物由脚本从归档目录派生 |

**可判定验收**：顶层 `conference/` 目录不存在；`competition/` 有分类定义；`python scripts/build_data.py` 能正常产出 383 条数据、`validate_data.py` 0 阻断错误。

## 3. 会议数据处理（回应学长建议②）

学长意见「原有会议数据后续需要丢弃，项目主要记录教育部白名单竞赛」。

- **当前动作**：384 份会议档案已整体迁至 `archive/conference/`，**未删除任何文件**，git 历史完整可回溯。
- **主线状态**：顶层数据源已切到 `competition/`，会议数据不再作为新增方向。
- **后续动作**：是否把 `archive/conference/` 彻底删除，待白名单竞赛数据成规模后由项目组拍板。**删除是不可逆操作，不在本次改动内。**
