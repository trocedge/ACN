# 项目范围与收录约定

> 状态：方向已按学长 2026-11-16 审计意见确认，具体白名单名单待官方来源填入。
> 本文只定「收什么 / 目录怎么组织」的口径，不删任何已有数据。

## 1. 项目主线

ACN 的主线收录对象是**教育部白名单竞赛**——由教育部公布、面向大中学生的全国性竞赛活动。会议（学术会议 DDL）属于从上游 `ccfddl/ccf-deadlines` fork 时继承的历史数据，不再是新增数据的重点方向。

- 新增数据优先顺序：教育部白名单竞赛 > 其它面向学生的赛事 / 活动 > 学术会议（仅维护已有，不新增）
- 判断依据：一条数据是否进主线，看它是否在「教育部白名单竞赛清单」里（见 `docs/whitelist-competitions.md`）

## 2. 目录命名约定（回应学长建议①）

学长指出「目录名依旧是 `conference`，但主要记录竞赛和活动，似乎可以规范化」。这里分清两层：

| 层 | 现状 | 约定 |
|---|---|---|
| 物理目录 `conference/**/*.yml` | 384 份上游继承的会议档案，`scripts/build_data.py` 等脚本硬编码依赖此路径 | **暂时保留原名**。改名会牵动全部脚本路径、CI 与前端产物，且与已合并 PR #1「老链路不变」的承诺冲突。改名作为独立任务，待白名单数据接入方案确定后统一处理 |
| 逻辑分类 / 前端展示 | 目前只有会议一种类型 | 新增竞赛、活动时，分类值用 `competition` / `activity`，与历史 `conference` 区分；前端筛选按分类值渲染 |

**可判定验收**：新增的每一条竞赛/活动数据，分类字段为 `competition` 或 `activity`，不写进 `conference/` 目录；历史会议数据保持原样、git 历史可回溯。

## 3. 会议数据处理（回应学长建议②）

学长意见「原有会议数据后续需要丢弃，项目主要记录教育部白名单竞赛」。

- **当前动作**：不删除任何会议数据。384 份档案是 git 历史的一部分，删除是不可逆操作，需项目组明确拍板。
- **过渡做法**：主线新增内容转向白名单竞赛；会议数据保留但不再作为新增重点，前端展示顺序与文档叙述重心同步调整。
- **后续动作**：待白名单竞赛数据成规模、且项目组确认后，再决定是否将 `conference/` 整体归档或移除。**该决定不在本次改动内。**
